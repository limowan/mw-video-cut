# mw-video-cut

**版本：1.0.0**

**口播剪辑：让 AI 当你的剪辑导演，从一份口播稿走到一条能发布的成片。**

真人出镜的口播视频（讲概念、讲工具、讲经验），从写稿、排分镜、录制，到转录剪口播、截图打码、配画面、质检渲染，再到三个平台的发布文案，一条流程走完。AI 在每个关键节点停下来给你看、等你点头，不会自作主张铺完整片再让你返工。

## 为什么这样剪

口播视频最常见的两种翻车：

- **一口气做完再给人看**：画风、节奏、动效密度不对，整片推翻重来。
- **画面只是把字幕放大**：观众看到的是"大字报"，而不是"演示"。

这个 Skill 的核心规则只有一句：**先样板后全片，画面演示不念字幕。**

## 一条主线 + 八道闸门

| 阶段 | 做什么 | 停下来确认 |
|---|---|---|
| ① 口播稿 | 先讨论再动笔，第一句就是全片要回答的问题；敏感词自查 | 🚦 定稿 |
| ② 分镜表 | 按画面变化分镜，一句一变，缺素材提前列出 | 🚦 分镜 |
| ③ 录制 | 你来录，素材放进项目文件夹 | |
| ④ 转录 + 删剪提案 | 逐词时间戳，按停顿切句，列口误和停顿压缩方案 | 🚦 删剪提案 |
| ⑤ 剪口播 | 只删口误和过长停顿，保留说话风格 | |
| ⑥ 截图打码 | 账号、App 名、域名、ID、姓名逐张打码 | 🚦 打码版 |
| ⑦ 视觉方案 | 一次出 3~7 套画风让你挑 | 🚦 选画风 |
| ⑧ 镜头表 | 逐镜写清：卡在哪个词、用哪张素材、什么背景 | 🚦 镜头表 |
| ⑨ 样板镜 | 先做一镜完整样板 | 🚦 样板 |
| ⑩ 全片 | 圆形头像固定右下、字幕逐字核对、动作卡在字上 | |
| ⑪ 质检 → 渲染 | 分批出静帧自查，再渲整片 | 🚦 成片 → 正片 |
| ⑫ 发布 | 小红书、B站、抖音各一份文案和 3 条标题；封面；归档；问你要不要删样片 | 🚦 文案、归档、删样片 |

两条防翻车的小规矩：

- **样片和正片分开放**：预览只进 `产物/样片/`，你确认后才复制到 `产物/正片/`，上传只从正片拿。
- **重活串行**：渲染和出静帧一次只跑一个进程，不会把电脑拖卡。

## 安装

将下面这句话发给支持 Skill 的 AI 编程工具：

```text
帮我安装一下 https://github.com/limowan/mw-video-cut 这个 Skill
```

也可以下载仓库后，将 `mw-video-cut` 文件夹放入当前项目的 Skill 目录。

第一次使用时，AI 会问你几个问题（口播稿放哪、用什么转录和配画面、发哪些平台），生成你自己的 `config.json`。

需要用到的其他 Skill（飞书、转录、画面、生图等），AI 会在对应阶段告诉你用途和安装命令，你同意了才装；不装也有替代做法。完整清单见 [references/工具与仓库.md](references/工具与仓库.md)。

## 怎么用

```text
帮我做一期口播视频：普通人靠 AI 能做出一款 App 吗？大概 3~5 分钟
```

```text
口播录好了，在 素材/原片.mov，帮我剪口播
```

标准流程是：

```text
口播稿 → 分镜表 → 录制 → 转录 + 删剪提案 → 剪口播 → 截图打码 → 视觉方案 → 镜头表 → 样板镜 → 全片 → 静帧质检 → 正片 → 发布文案 + 封面 → 归档
```

## 适用边界

- 适合**真人出镜的口播视频**：讲概念、讲工具、讲经验。纯动画科普、带货、Vlog 不是它的主场。
- 它管流程和思路，具体的转录、剪辑、渲染由对应工具完成，效果取决于你装了哪些工具。
- 转录会把音频上传到你配置的服务（例如火山引擎），上传前 AI 会征求你的同意。
- AI 仍可能出错：删剪时间点来自转录，剪完请抽听；成片请自己完整看一遍再发布。
