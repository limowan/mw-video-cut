# 口播视频分镜指南

**适用范围：真人出镜的口播视频**（讲概念、讲工具、讲经验），写口播稿、排分镜、剪辑时参考。

原则来自几支科普短片的实测和爆款口播视频的拆解，按真人口播的情况做了调整。

**这是参考，不是模板。** 每条都写了为什么，按片子的情况取舍；秒数只是量级。流程和工具也不固定，见文末。

---

## 一、选题和开头

- **能用一句具体的问题问出来**：“不会写代码的人，真能做出一个 App 吗？”比“今天聊聊 Vibe Coding”更能留住人。观众一看就想知道答案
- **答案几步就能讲完**：因果链太长的题，观众听一半就走
- **第一句就是全片要回答的问题**：具体、反常识，最好和发布标题是同一句话。不用“大家好，今天给大家分享……”“最近有个词很火”这种铺垫开场
- **标题前置**：0–3 秒内标题大字压上画面，跟第一句同时出现，不等开场白说完
- **第 0 帧就要完整**：真人已经在画面里说话，或者直接是标题 / 关键画面。不从黑屏、片头、Logo 淡入
- **3 秒内至少一次明显的画面变化**：推近人像、标题砸出、切到关键截图都算。科普片实测：前 2 秒没东西的片子，2 秒跳出率过半

## 二、结构（按比例，不按固定秒数）

```
开场     0–10%   问题 + 标题，先抛结论或冲突
证据     10–60%  真实操作、截图、录屏、案例、数字；一段只讲一件事
提炼     ~60%    一句话说清核心观点（能截图转发的那种）
转折     ~65%    “但是”：拆一下自己，讲适用边界或反例
回到观众 65–90%  这跟你有什么关系、你现在可以怎么做
收尾     后 10%  一句短的结论 + 收尾钩子（文档换点赞收藏关注），放在最后，不占开头
```

- 转折段是可信度的来源：只讲好处，观众会觉得在推销
- 收尾回到开头那个问题，观众会觉得“完整”
- **收尾钩子（每期都要有）**：结论之后，用一句"文档换关注"收尾，句式：
  > 我把＿＿＿整理成了一份文档，只为换取你手里的点赞、收藏和关注，我们下期再见。
  - 空格里填本期**具体、可数**的干货，比如"这 7 条指令""开发 App 的完整流程""搭知识库用的提示词"，越具体越有吸引力；不要写成"相关资料"这种空话
  - 文档要真的准备好，评论区或主页能拿到；没有就不说，别开空头支票
  - 写稿阶段就把这句写进口播稿结尾，不要录完再补；画面上配文档卡 + 点赞、收藏、关注依次点亮

## 三、口播稿

- **一句一个意思**：口语短句，一句 2–5 秒说完；长句拆开说
- **先结论，后解释**：每一段第一句就给判断，后面再展开
- **对比句、硬数字、人名 + 年份**：让信息有抓手（“2025 年 2 月，Karpathy 发了一条推文”比“前段时间有人说”有说服力）
- **爽点**：被说中、认知反转、数据砸脸、替你正名、笑点、悬念回收、社交货币。口播比纯动画慢，大约每 10–15 秒一个；写完数一遍，太稀就补
- **数字和说法要能核实**：拿不准的用约数，画面和口播说法一致
- 平台敏感：避开“最好”“第一”“官方认证”这类绝对化说法

## 四、画面节奏（重点）

纯动画科普片能做到 2 秒一变；真人口播 2 秒切一次会显得碎、躁。口播的节奏这样把握：

- **一句一变**：每句话（或每 3–6 秒）至少一次明显的画面变化
- **同一画面不超过 6 秒**：同一景别的人像、同一张截图，连续超过 6 秒就打断一下
- **开头和高潮可以更快**：开头 3 秒、观点砸下来的地方，可以 2 秒一变
- **观点段、情绪段可以放慢**：给脸、给停顿，节奏感来自快慢的反差，全片不能一个速度
- **说到就出现**：截图、关键词大字在说到那个词的瞬间出现（用逐词时间戳卡准），不提前、不拖后
- **画面变化卡在重音上**：一句话的重点词、数字出现时，画面同步变化

**变化手段库**（口播常用，优先级从上到下）：

| 手段 | 什么时候用 |
|---|---|
| 切到截图 / 录屏（人像缩成小窗） | 讲到具体工具、页面、操作、数据时 |
| 关键词大字 / 数字砸出 | 定义、结论、数字、转折词 |
| 截图局部放大、滚动、圈注、高亮 | 截图停留超过 3 秒时，用镜头运动带着看 |
| 人像推近 / 拉远（跳剪） | 连续说话、没有素材可切时；强调句推近 |
| 全屏人像 ↔ 小窗人像互切 | 段落切换、从讲解回到表达观点 |
| 图示、对比卡、流程图 | 讲“A 和 B 的区别”“三步”“结构”时 |

## 五、看知识，不是读知识

- **画面本身要能讲明白**：把字幕遮掉只看画面，也能大致看懂这一句在说什么。画面只给口播当背景板的，就要重做
- **截图不整页缩小**：整页截图缩到画面里，字小到看不清，等于没放。用局部放大、滚动巡游、圈注承接讲解
- **一屏一个重点**：同一时间只让观众看一样东西，其他的压暗或移走
- **字幕和画面文字不打架**：画面上的大字和底部字幕不重复同一句，不互相遮挡
- **不伪造**：示意动画不说成真实录屏，没有的操作结果不画出来

## 六、标题和封面

- **标题**：可以用这个句式，`《主题》+ 反常识的一句话 + ：+ 一个算式或数字`（例：《Vibe Coding》不会写代码也能做 App：0 行代码 = 1 个小程序）。也可以就用开头那个问题
- **封面**：一个具体的问题 + 一个看得见的答案；封面标题和第一句、发布标题保持一致
- 3:4 和 4:3 各一张；标题文字可以直接写进生图提示词让模型画，生成后核对错字

## 七、分镜表怎么写

写口播稿时，节奏就要排好，不留到剪辑时再想。分镜表写在飞书文档里，列和飞书模板保持一致：

| 镜号 | 口播脚本（逐字稿） | HTML画面（背景） | 画面备注 |
|---|---|---|---|

- 镜号按画面变化分，不按段落分：一句话或一次明显变化就是一镜
- HTML画面：写这一镜画面怎么变，用的是变化手段库里的哪一种
- 画面备注：预估秒数、关键词大字、素材、爽点，都写在这一列
- 每一镜都写清“画面怎么变”，空着的镜头，剪辑时大概率就是一张脸撑全场
- 一镜超过 6 秒的，标出中途的第二次变化
- 画面备注里写清用哪张截图、哪段录屏；缺素材的单独列出来，开拍前补

## 八、质检

- **前 3 秒单独看**：第 0 帧有没有人、有没有字，标题出没出来，3 秒内有没有变化
- **抽帧联系表**：逐段抽帧拼图，查截图看不清、文字重叠、字幕压画面、人像被挡
- **节奏测量**：用 FFmpeg 的场景切换检测（`select='gt(scene,0.3)'`）找出成片里的大变化时刻，看平均间隔和最长空档。真人头像一直在动，"有没有静止"对口播意义不大，主要看"最长空档"；超过 10 秒没有大变化的段落，回去看是不是该切素材
- 发布后看 2 秒跳出率、5 秒完播率；跳出率高先查前 3 秒

## 九、画面做得好看的几个做法（参考）

来自 2026-10「自己搭一个投稿工作台」那期的实践，可参考，不是固定流程；按片子内容和形式灵活调整，不拘泥于某个 Skill 或卡库。

**做之前先对齐**

- 每次动手剪辑前，先给用户确认分镜；再做一镜样板确认风格、动效密度、音效音量，确认后才铺全片
- 视觉方案多出几个让用户挑（配色、底色、字体气质、动效风格），不只给一个
- 标准按商用级、获奖作品来要求，不做"能看就行"的版本
- 已经准备好的素材（项目 `素材/`、`共享素材/` 里的图片、截图、视频）该用就用进画面；排分镜时发现还缺什么素材，主动列出来提醒用户去准备，不默默用纯动效糊过去

**画面演示，不复述字幕**

- 讲解画面用截图和动画"演"出来，不把这句话放大成大字压上去。那期第一版就是因为每帧都在复述字幕，被整个推翻重做
- 画面上可以有字，但只限演示用的界面文字、文件名、数字，不跟字幕说同一句话

**动效先选"配方卡"再换皮**

- 每一镜先选一个现成动效当主卡（放大镜、数字滚动、光标点击、急推、扫描线、粒子重组……），来源可以是 video-talkcraft 卡库、HyperFrames 组件，也可以自己设计
- 选好后只换皮：颜色、字体、素材换掉，时长、缓动、幅度这些动作参数不动。"看着专业"主要靠这些调好的手感
- 一镜一个主角，说完压暗让位、留在原位不退场，下一个主角不摆进它的位置

**动作卡在字上**

- 用逐字时间戳，动作起点对准那个字（说到"49 天"的"了"，数字开始滚）
- 还没说到的数字和图形完全不显示，不先半透明挂着预告
- 动作落点离这一镜结束至少留 0.5 秒，不然会被转场吃掉

**转场和底色**

- 转场全片一套：下一镜从 1.06 倍落回并淡入，上一镜同时往前冲一点；每镜内部再加一个极慢推近（1→1.03），画面一直在呼吸
- "同一件东西换了个形态"可以用粒子打散重组，全片最多一次，多了就廉价
- **背景不要全片固定一种**。配色骨架不变（同一个强调色），按段落换底：深色、浅灰、暖纸、冷灰细网格，结尾可用品牌色满屏；深底上字幕和强调色跟着换浅色

**截图**

- 自己能启动的产品，用演示数据在本机截图（只读，不改文件），比用别人的真实数据安全
- 圈注、放大镜、高亮框的位置按截图像素量出来，不目测；目测偏几十像素就会框错东西
- 他人真实数据（未发表稿件、客户信息）要打码，发布前取得对方同意；没有真实对应物的示意界面，画面上标「示意」

**竖屏**

- 左右分屏、左右滑动对比在竖屏上常读不清，改成上下对照
- 内容区放在字幕带上方，避开真人头像（用右下圆形头像时就是右下角）

**自查和声音**

- 整片渲染前，先批量出静帧拼联系表自查；一次打包出几十张图，比整片渲快很多，改完再整渲
- 音效跟着动效走，主要动效入场都配；音量压在人声下（约 0.3 以下）
- 成片两遍响度归一化到约 −15 LUFS

**剪口播的小坑**

- 原片音画有偏移的，先补齐再剪
- 找停顿时 OpenEdit 默认 −62 dB 门限太严，呼吸声会被当成说话；那期实测 −50 dB 合适

## 十、流程和工具（参考，不固定）

常见的路子：

```
选题 → 口播稿 + 分镜表 → 拍摄 → 转录、剪口播 → 画面和动效 → 抽帧质检 → 成片 → 封面 + 发布文案
```

工具按项目选，可以换：每个环节用什么，以 Skill 根目录的 `config.json` 为准（字段见 `config.example.json`）；可选工具和仓库地址见 `references/工具与仓库.md`。
