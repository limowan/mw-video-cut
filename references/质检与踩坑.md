# 质检与踩坑

## 静帧质检清单（⑪）

出联系表后逐张看，每镜至少两帧（入场后约 0.6 秒、结束前约 0.6 秒）：

- [ ] 第 0 帧就有画面和字，3 秒内有一次明显变化
- [ ] 内容没压到底部字幕带、真人头像、左上章节标
- [ ] 用圆形头像时，开头、中间、结尾三处的头像里额头到下巴都完整，脸没偏出圈
- [ ] 全屏真人镜头里，文字、卡片、字幕及其背景没有进入人脸安全区
- [ ] 深底上字是浅色、浅底上字是深色，都看得清
- [ ] 没有大字复述字幕（金句卡、关键词卡也要警惕：和同时出现的字幕一字不差就改成画面演示）
- [ ] 没有空台：每镜都有主角，"说到之前什么都不显示"的空档不超过 2 秒
- [ ] 截图看得清：整页太小就裁局部、放大镜、急推
- [ ] 打码无遗漏：App 名、图标、域名、账号、ID、姓名、厂商名
- [ ] 画面和成片文字里没有具体平台名、云厂商名、绝对化用词
- [ ] 背景相邻镜不重复，深浅交替
- [ ] 排版没崩：中文标签被挤成竖排，多半是外层容器没给宽度，加宽度或 `white-space: nowrap`

渲完成片再查：时长对得上、抽 12 帧左右、平均响度（需要时两遍归一化到约 −15 LUFS）。

## 踩过的坑

### 流程

- **跳过样板直接铺全片**：画风、动效密度用户不认，整片推翻。每次新风格都先做一镜样板。
- **每帧都是大字**：用户第一反馈就是"为什么每页都是大字"。画面要演，不要念。
- **只给一套视觉方案**：用户没得选，容易反复改。至少给 3 套。
- **自动切字幕切断词**：字幕手工按实际口播断句，再和转录逐字核对。

### 渲染与机器

- **多个 AI 会话并行渲染 / 出静帧**：每个会话各起打包器和一堆无头浏览器，机器直接卡死。全程只跑一个渲染进程。
- **外部 AI 会话停掉后留下孤儿进程**：每个会话启动时会带起一套 MCP 服务进程，停会话后可能不退出。卡顿时先查进程，只清理自己启动的，用户自己的应用不要动。
- **一次出几十张静帧**：同样会拖慢机器。分批，每批十几帧。
- **整片一起渲**：默认开 8 个浏览器截图，改一个镜头也要整片重来。用 talkcraft 的分段渲染，4 段并行，只重渲改动的镜头；编码交给显卡（Remotion 4.0.484+ 支持 Windows NVENC）。
- **渲染失败只看到最后几行**：输出被过滤就看不到报错原因。渲染日志完整写进文件再查。

### 环境（Windows）

- 中文路径在 git-bash 里可能变乱码，涉及中文路径的命令用原始 Windows 路径或 UTF-8 读取；看到乱码就停，不基于乱码输出做删除、移动。
- JS / JSON 字符串里的 Windows 路径反斜杠写成 `\\`。
- `mklink /J` 在 git-bash 里会被改坏，用 PowerShell `New-Item -ItemType Junction`；git-bash 的 `ln -s` 在没开开发者模式时会变成整份复制。
- 链到别的旧项目的 Remotion 版本旧、缺包，遇到缺包只能删效果凑合；统一用 talkcraft runtime 那一份。
- PowerShell 可能禁止运行 `.ps1` 脚本（执行策略），不要为此改系统设置，换 node / python 脚本。
- Remotion 的 GLSL / WebGL 背景需要 ANGLE：配置里开 `Config.setChromiumOpenGlRenderer("angle")`，脚本出静帧时传 `chromiumOptions: { gl: "angle" }`。

### 剪口播

- 原片音画有偏移（例如音轨晚 0.1 秒），先补齐再剪。
- 静音门限 −62 dB 太严，呼吸声被当成说话；−50 dB 合适。
- 删剪提案的时间点来自转录，执行后抽听切点。

### 真人头像

- 圆形头像是按一个固定中心点裁的，不会跟着人脸动。这一期坐得正、不怎么晃没问题；换了机位或人往边上挪，脸就会偏出圈、下巴被切。每期都要先抽帧定位，再做样板确认。
